Gaggiuino secure firmware flasher

ESP32-P4 and ESP32-S3 · Release / Dev · ROM-only flash · SPI attach fix

Development prototype. Use Chrome or Edge on HTTPS/localhost with the device in ROM download mode. Flashing pre-encrypted images is for boards provisioned with the matching encryption key.

No chip erase. This tool writes only the selected manifest images at the configured offsets. It never changes eFuses. Flash encryption in Release Mode cannot be undone; wrong ciphertext or a wrong bootloader may prevent normal boot.

Development here means the firmware build channel, not ESP-IDF flash-encryption development mode. Release-locked boards still require correctly pre-encrypted images for this exact device and offset.

3 · Select operation
HIGH RISK: System image rewrite. This mode replaces the bootloader, encrypted partition table and NVS image, in addition to both apps and webdata. This is not a whole-chip factory erase: OTA metadata, tempdata, coredump and other untouched partitions remain as-is. Make sure all encrypted files match this board's key and the exact offsets. On S3, verify the actual NVS partition size against your partition CSV.
4 · Safety acknowledgement
ROM connection fix: SPI flash is explicitly attached before applying 16 MB parameters. The flasher uses 64 KiB erase/write batches to avoid a multi-megabyte ROM erase timeout, and Web Serial byte-level tracing is disabled. If a command fails, the log identifies its stage. Hardware validation is still required.

Files are resolved from the selected release/dev manifest beside this HTML page; binary paths are relative to the manifest. 16 MB flash is assumed for both targets. No other applications may have the COM port open.

Ready
Ready. Put the board into ROM download mode (BOOT + RESET), then select its COM port.

Dev channel swaps only the application binary paths via a separate manifest. Bootloader, partitions, NVS and webdata can be shared, but must be compatible with that firmware build. Built on esptool-js@0.7.0 Web Serial. ROM flashing (no stub), raw data (no compression), 1 KiB ROM blocks, explicit SPI_ATTACH and 16 MB SPI_SET_PARAMS, with 64 KiB erase/write batches. Successful writes mean ROM acknowledgements only; secure download mode may prevent readback verification. The reset may require unplugging/replugging USB.
